## 2. Решения владельца и правила работы

### Что это за продукт

«Запятая» — тренажёр ОГЭ по русскому языку для владельца и его одноклассников. Это устанавливаемый сайт/PWA с молодёжным интерфейсом в духе iPhone, фиолетово-лаймовой палитрой, узнаваемой запятой, мягкими короткими анимациями, офлайном и сохранением прогресса на устройстве. Главные пять функций: тренировка по темам и номерам ОГЭ, мини-варианты на время, повторение ошибок, теория с конкретными разборами, статистика. Позже согласованы диагностика, дневной маршрут, интервальные повторения, шесть учебных механик, спокойный опыт и облако класса.

### Явные разрешения и последующие изменения требований

1. Первоначально владелец просил push и публикацию только по отдельной команде. Затем **прямо разрешил в этой сессии commit, push, настройку GitHub Pages и запуск деплоя**. Дальше просил публиковать небольшими проверенными порциями. Это разрешение уже использовано для существующих выпусков.
2. Первоначально пособие предполагалось держать локально, а публично выпускать демозадания. Позднее владелец спросил, можно ли загрузить все задания в GitHub, и **явно выбрал «Опубликовать банк для всех в GitHub»**. Поэтому публичный `public/packs/praktikum-2027.json` намеренный. Не возвращать ограничение «только демо» из старых промптов.
3. **Сам PDF, сырой извлечённый текст, рабочие отчёты, локальные корректировки и секреты остаются локальными/приватными.** Решение о публичном банке не означает разрешения выкладывать PDF, токены, персональные данные или пользовательский прогресс.
4. На первый большой промпт получен ответ: **«Сначала завершить P0/P1, затем импорт»**. На второй: **«Да, выполнять план из файла»**. Прикреплённые инструкции применены по подтверждению пользователя, но их устаревшие ограничения не отменяют более поздние решения.
5. Пользователь многократно просил «продолжай», «до конца пока лимиты не кончатся за один заход». Предпочитает самостоятельное выполнение существенного объёма, без бесконечных предложений «могу сделать дальше» и повторных подтверждений уже разрешённых действий.
6. Самый свежий запрос на изменение приложения: **«К каждой вот такой теории нужно сделать красивый визуал структурированный»**, со скриншотом длинной моноширинной теории «Грамматическая основа». Этот этап выполнен и опубликован, детали ниже.
7. Последний запрос — **только подготовить этот подробный MD для перехода в новый чат**, не продолжать параллельно разработку.

## 3. С чего начиналась поломка и что исправлено

GitHub Pages публиковал исходную ветку/корень проекта вместо результата Vite. HTML пытался загрузить **`/src/main.tsx`**, получал 404, экран оставался белым. Недостаточно было того, что локальный dev-сервер работал.

Исправление: Pages использует **GitHub Actions**, workflow устанавливает зависимости по lockfile, проверяет и собирает приложение, публикует **`dist`**, вычисляет базовый путь по фактическому имени репозитория. Для этого сайта путь **`/Ekzamen-9-klass-rus/`**, маршрутизация через HashRouter. Проверены JS/CSS, manifest, иконки, worker, прямой вход в каталог, офлайн и обновления с сохранением состояния.

**Не возвращать Source → Deploy from a branch на сырые исходники.** Сейчас Pages workflow запускается вручную (`workflow_dispatch`), обычный push сам по себе его не запускает. Подробности в разделе 13.

### Помощь, повторение, дневной маршрут, опыт

- Открытая до проверки подсказка/теория фиксируется как помощь; нельзя задним числом сделать помогавшуюся попытку самостоятельной. Повторная отправка и двойное «Далее» идемпотентны.
- Повторение обычных задач и карточек: **1/3/7/14 календарных дней**, до 5 за подход. Ошибка/помощь/частичная самооценка возвращают короткий интервал; досрочный правильный ответ не удлиняет срок. Используются локальные даты устройства, а не сутки по 24 часа/UTC.
- «На сегодня»: примерно 10–15 минут, **без обязательного таймера**. До пяти повторений из обычных задач и карточек, следующий короткий урок, два обычных вопроса разных номеров при наличии. Демо: правило, пример, два вопроса.
- Дневной состав фиксируется при старте, переживает смену дня. Незавершённый прошлый маршрут продолжается. Один завершённый план на назначенный день.
- Обычные ответы из дневного маршрута входят в общий прогресс один раз; учебные преобразования учитываются отдельно.
- XP вычисляется из сохранённых событий, а не из произвольно увеличиваемого баланса. Одно событие не начисляется повторно, максимум **100 XP в день**. Старый опыт сохраняется при ревизии задачи.
- Примерные правила начисления текущей версии: первое самостоятельное обычное решение 10; повторение по сроку 5; первое учебное решение 5; урок 15 раз в день на урок; дневной план 5 раз в день; честная самооценка 2 при знакомстве/сроке, независимо от оценки себя. Помощь не приносит награду за самостоятельность.
- Уровни без наказания за перерыв, пороги 0/50/150/300/600; четыре достижения: первое самостоятельное решение, урок, исправленная ошибка, семь разных дней. Последовательная ежедневная серия не требуется, XP за пропуск не отнимается.
- Подсчёт опыта оптимизирован до последовательного прохода; есть проверка истории на 1600 ответах.

### PWA, локальный PDF, внешний вид

- Установка/PWA, светлая и тёмная темы, нижняя мобильная навигация, боковая панель на широком экране, SVG/CSS бумажная запятая со сгибом и тенью. WebGL для этого не нужен.
- Обновление приложения предлагается вне экрана текущего ответа, в том числе при существовании незавершённых черновиков на главной. Прогресс не удаляется.
- Пособие скачивается из библиотеки, сверяются размер, SHA-256 и схема, пакет сохраняется для офлайна. Обновление банка — отдельное действие от обновления приложения.
- Локальное открытие исходного PDF до 20 MB, проверка SHA-256 нужной редакции, просмотр страниц/масштаба/текста, отдельная IndexedDB для файла. PDF не отправляется в сеть. Удаление PDF не удаляет прогресс.
- PDF.js и его `.mjs` worker входят в офлайн-кеш; это существенно для работы просмотра без сети.
- Широкие таблицы на мобильном имеют понятные кнопки перехода «Начало / Остальные столбцы».

## 6. Последний завершённый этап: красивая структурированная теория

На пользовательском скриншоте теория «Грамматическая основа» представляла собой большой моноширинный исходный текст внутри карточки. Владелец попросил красивый структурированный визуал **для каждой такой теории**.

Выполнено и опубликовано в `4b27aa9`:

- **47 авторских визуальных конспектов** для всех известных разделов пособия + **10 правил демо**.
- Вводная мысль, схема (категории, последовательность или состав по теме), карточки правил, два конкретных разбора с выделением, три шага решения и типичная ошибка. У ряда тем сравнительные шпаргалки.
- Основа предложения подчёркивается как подлежащее/сказуемое, выделения безопасно разбираются как текст, без вставки произвольного HTML.
- Навигация по разделам с прокруткой/фокусом, не меняющая URL/черновики. Клавиатура и reduced-motion.
- Полный исходный фрагмент **не удалён**: раскрываемый блок + ссылка на PDF. Конспект честно назван авторским учебным материалом, а не дословным полным источником.

## 10. Инварианты, которые легко сломать

### Версии контента и статистика

- Структурированный пакет со схемой; задания single/multi/positions/boolean/text/matching/self, ответы строка/массив/отображение. Блоки поддерживают обычный текст, заголовки, списки, таблицы, выделения и preformatted.
- ID адресует издание/раздел/тему/текст/вопрос. Не использовать один локальный номер как уникальный ключ всего пособия.
- У попытки есть версия задачи, режим, время/локальная дата и помощь. Результаты correct/wrong/skipped/self различаются.
- Текущая точность и ошибки фильтруются по актуальным ID/версиям. История старых версий остаётся; старый XP не пропадает.
- **Изменение ключа, принимаемых форм, типа или условия требует повышения версии задачи.** Замена отметки `rules` → `manual` допускается без повышения только если остальные данные тождественны.
- Импорт отклоняет другой контент под тем же `packVersion`, а также изменённую задачу с прежней версией. Не обходить защиту ради удобства.
- `12` в исходном ключе может означать позицию 12 или позиции 1+2 в зависимости от формата блока. Нельзя глобально разбить все числа на цифры.
- Морфология, порядок пар, пробелы, Е/Ё и дефисы нормализуются по явно разрешённым правилам конкретного задания. Не применять всеобщую нечёткую проверку.
- `self`/`reviewRequired` не участвуют в объективной точности, мини-вариантах/диагностике; никакой выдуманной автопроверки.

### IndexedDB, черновики, повторная отправка

- Основная база **`zapyataya-v1`**, текущая схема Dexie **v4**. В нативном IndexedDB номер может отображаться **40**: это масштабирование Dexie, не потерянная миграция.
- v1: packs/sessions/attempts/settings; v2 learningSessions; v3 punctuationSessions; v4 studySessions. Разные режимы имеют свои черновики.
- Мутации сериализуются. **Не вызывать из уже выполняемой сериализованной операции другой сериализованный публичный API с await**: можно получить взаимную блокировку очереди.
- Транзакции включают все читаемые/изменяемые таблицы; у Dexie использовать подходящий overload с массивом. Ошибка записи не должна частично затереть состояние.
- Проверять ожидаемый ID активного шага. Проверка/«Далее» идемпотентны, сохранённый оценённый ответ неизменяем. Последний открытый режим определяется `lastOpenedAt`, а не случайным порядком массива.
- `StudyAttempt.canonical` содержит обычную попытку из дневного маршрута; snapshot объединяет её с основной таблицей. **Не записывать её ещё раз в `db.attempts`**, иначе статистика и XP удвоятся.
- Выбор/поля сохраняются без потери последних символов: учитываются незавершённые записи и актуальный ref. Не блокировать текстовый ввод на каждом сохранении символа.
- Для слов основы стабильные ID вида activity.wN и диапазоны Unicode-слов; отображать исходную строку со всей пунктуацией. Не склеивать предложение обратно из списка слов.
- Подсказки фиксируются до проверки; нельзя последующим закрытием теории стереть факт помощи.

### Повторение и опыт

- Локальный календарный день важнее UTC; DST/24 часа не подменяют переход календарной даты.
- Обычный тренажёр и карточки используют общий смысл переходов интервала, а XP вычисляется согласованно с ним.
- Карточка, выполненная внутри дневной серии, определяется по типу/префиксу активности, а не только `session.mode==='cards'`.
- Исторические события дедуплицируются по ID; смена источника/повторный рендер не начисляют награду ещё раз.
- Самооценка честно остаётся субъективной и не притворяется объективной правильностью.

### PWA и локальный файл

- PDF хранится в отдельной базе **`zapyataya-local-source`**, v1, таблица files; не включать Blob в пакет/попытки/будущее облако прогресса.
- При обновлении worker надо дождаться **реальной навигации**: `Promise.all([page.waitForNavigation(), click])` или эквивалент. Один `waitForLoadState` на уже загруженной странице когда-то дал гонку теста. Приложение затем повторно проверено с правильным ожиданием.
- `.mjs` PDF worker и lazy-модули/стили конспектов должны входить в precache. PWA проверять на production build/preview/публичном сайте, dev-сервер не доказывает офлайн.
- Чтение теории не должно менять ответы, XP, режим, пакет или прогресс.

Просроченные карточки объединяй в посильный объём. Каталог всего материала и свободная практика доступны постоянно.

Выбери спокойную мотивацию — личная цель, видимый прогресс тем, опыт и несколько достижений за полезные действия. Засчитывай завершение урока, самостоятельное первое решение и назначенное повторение. Повторное нажатие или повторная отправка события дают одно начисление. Одно и то же простое упражнение даёт ограниченный опыт за день. Ученик может вернуться после перерыва и продолжить маршрут. Уровни называй нейтрально и поясняй, за что они получены.

В прогрессе отдели первичную диагностику, обычную практику, интерактивы и мини-варианты. Покажи самостоятельную точность, решённые вопросы, назначенное повторение и динамику по темам с числом попыток. Малое число наблюдений обозначай понятно. Если есть 21 материал и 20 автоматически проверяемых вопросов, объясни этот состав прямо в интерфейсе. Проверь склонения числительных во всех состояниях.

## 4. Авторское визуальное направление

Развей образ «Запятой» как мастерской, где из текста складывается понимание. Главный объект — объёмная запятая из плавно согнутой бумажной ленты. Внутри интерфейса её изгиб повторяется в траектории прогресса, курсоре выделения и мягких углах карточек. Используй крупную читаемую кириллицу, ясную сетку и небольшие графические детали, связанные с языком.

Светлая тема может сочетать тёплый почти белый фон, графитовый текст, насыщенный фиолетовый и точечный лаймовый акцент. В тёмной теме используй глубокий графит, светлые буквы и приглушённые поверхности. Проверь контраст реальных пар цветов и все состояния полей и выбора. Источник шрифта должен поддерживать кириллицу, а необходимый шрифт и иконки — работать офлайн.

Главная начинается с следующего действия ученика. Рядом на широком экране размести компактную сцену с запятой и текущим учебным шагом. На телефоне ограничь высоту графики, чтобы действие было легко найти. Каталог тем содержит понятные названия, подтемы и прогресс. На десктопе избегай длинной колонки, где маленькая карточка занимает широкую пустую строку. Страница урока показывает маршрут шагов. Режим решения даёт достаточно места тексту и варианты, которые легко нажимать.

Рабочие ориентиры — иерархия и спокойная плотность интерфейса Linear, внимание Stripe к реакции объёмного объекта на действия. Создай собственную композицию, форму запятой и язык учебных состояний. Декоративные сцены размещай в местах, где они помогают ориентироваться или отмечают завершение.

## 5. Объём и анимации

Начни с CSS, SVG, градиентов, перспективы и небольших `transform`, чтобы создать ощущение глубины и движения. Сделай объёмную запятую, карточки уроков с лёгким рельефом и короткое складывание отметки после полезного действия. Реалистичность материалов можно выразить светом, тенью и перекрытием слоёв. Эти эффекты исполняются в браузере.

Сцену с настоящей 3D-геометрией на Three.js или уже используемом движке добавляй после завершения обязательных функций, если она даёт заметный выигрыш. Создавай геометрию программно, загружай сцену лениво, ограничь pixel ratio и приостанавливай рендер вне экрана и при скрытой вкладке. Для ошибки WebGL, уменьшения движения и слабых устройств должен быть готов статичный SVG. Обычный каталог и урок открываются независимо от загрузки декоративной сцены.

| Событие | Ожидаемое движение |
| --- | --- |
| Выбор варианта | Короткая реакция рамки, цвета и значка примерно за 120–160 мс. |
| Выделение слова | Подсветка и чёткое состояние выбранной роли, без сдвига строки. |
| Проверка | Появление объяснения и подсветки нужного фрагмента примерно за 180–250 мс. |
| Следующий шаг | Короткий переход, фокус на заголовке и предсказуемая позиция прокрутки. |
| Завершение урока | Один спокойный акцент на прогрессе и ясная кнопка следующего действия. |

Поддержи `prefers-reduced-motion`, видимый фокус и подписи элементов. Основные зоны касания от 44 × 44 CSS px. Для динамических результатов используй умеренные объявления скринридеру. Таймер сохраняет спокойное отображение и корректную работу в фоне. Уведомление о готовности офлайна компактно и исчезает после подтверждения.

## 6. Необязательный ИИ-помощник

ИИ — дополнительная возможность после готовности остальных функций. Подготовь изолированное включение через настройку. Базовое обучение, ключи, диагностика и разборы должны работать на локальных проверенных данных.

Если ключ провайдера и серверная функция уже доступны, реализуй вопрос «Объясни этот шаг» для текущего задания. Запрос идёт через сервер или Supabase Edge Function с проверкой аккаунта, ограничением частоты и объёма. Используй минимальный релевантный фрагмент условия и теории. Секрет хранится на сервере. Ответ помощника оформляй отдельно от проверенного ключа. При тайм-ауте доступны обычный разбор и правило.

Если провайдер пока не подключён, сохрани короткую инструкцию включения в README и отключи функцию по умолчанию. Изучи актуальную официальную документацию выбранного API перед его подключением. Подписка ChatGPT Plus и биллинг API рассматриваются отдельно. Автоматическое подключение платного сервиса требует явного решения владельца.
